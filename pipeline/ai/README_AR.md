# ربط نموذج الذكاء الاصطناعي التجريبي بموقع Fire Guardian

هذه إضافة برمجية مبنية على نسخة المستودع التي كان إصدار الموقع يشير إليها: `c105a4d`، وفُحصت صحتها محليًا باستخدام بيانات واختبارات فعلية. **الإضافة غير مرفوعة إلى GitHub وغير منشورة في الموقع بعد**؛ يلزم تطبيقها في مستودع الفريق وتشغيل اختبار البناء ثم النشر.

## إلى عبدالله: التوصيل السريع

1. ضع `fireguardian-ai.patch` في مجلد المستودع، وافحص أن نسخة الفرع متوافقة وأن التغييرات المحلية محفوظة.
2. من مجلد المستودع نفّذ:

```bash
git apply --check fireguardian-ai.patch
git apply fireguardian-ai.patch
npm ci --prefix api
npm run typecheck --prefix api
npm ci --prefix web
npm run build --prefix web
```

إن فشل `git apply --check` فلا تنفّذ التطبيق قبل مراجعة اختلاف ملفات الموقع عن نسخة `c105a4d`. التعديل يضيف مكون واجهة واحدًا، ونقطة API، ومعاملات النموذج، ومكتبة الحساب. ثم يُراجع وينشر بالطريقة المعتادة للمستودع وVercel.

3. بعد التشغيل أو النشر، اختر من الخريطة موقعًا في نطاق جازان أو عسير أو الباحة ضمن الخلايا التي شملها التدريب. البطاقة الجديدة تعرض مؤشرًا بحثيًا مبنيًا على طقس NASA POWER؛ وإذا كانت البيانات ناقصة أو الخلية خارج النطاق تعرض رسالة بدل اختلاق قيمة.
4. يمكن فحص نقطة API مثل `/api/ai-predict?lat=18.5&lon=42.5`؛ ترجع **503** عند نقص بيانات NASA أو وقوعها خارج نطاق التدريب، و**422** لمركز غير مدعوم. لا تستخدم بيانات الطقس الوهمية للموقع كبديل.

ملاحظة: تحتاج هذه العملية إلى شخص لديه صلاحية التعديل في مستودع GitHub؛ لا تحتاج مفاتيح API جديدة من المستخدم لجلب NASA POWER في هذا المسار. قد تفشل مكالمات NASA أو تتأخر البيانات، فتظهر رسالة بعدم توفر النتيجة.

## ماذا يفعل النموذج؟

هو انحدار لوجستي متدرّب على الرصود التاريخية وأرصاد NASA POWER، ثم ضُبط على فترة لاحقة. يتوقع **مؤشرًا استكشافيًا مرتبطًا برصد VIIRS لبؤرة حرارية مصنّفة نباتية في خلية**؛ وليس احتمالًا موثوقًا لاندلاع حريق. لا تصفه كنظام تحذير أو كنسبة دقيقة لاندلاع الحريق. عرض القيمة على مقياس 0–100 هو مؤشر للنموذج وليس نسبة مؤكدة لاحتمال الحريق.

المدخلات هي متوسط الحرارة وأعلاها، والرطوبة وسرعة الرياح والهطول من NASA POWER، إضافة إلى الموقع والموسم. حداثة البيانات مهمة: تستخدم التجربة ملخص طقس UTC من **ثلاثة أيام قبل يوم الرصد المستهدف**، لأن هذا يقلل مشكلة تأخر البيانات التي اختبرناها؛ إذا لم يكن ملخص ذلك اليوم متاحًا، لا تُنتج نتيجة. لم يُختبر توفر كل موقع في كل وقت، وقد تتأخر البيانات أو تتغير لاحقًا.

تحدد الواجهة غدًا حسب تاريخ السعودية، ويغطي اليوم المستهدف UTC من **03:00 صباحًا بتوقيت السعودية في ذلك التاريخ إلى 03:00 صباحًا من اليوم التالي**. تكتب الواجهة الفترة كاملة. النطاق 29 مركز خلية بحثية في أجزاء من جازان وعسير والباحة فقط. قياس الطقس الأصلي نحو 0.5° عرض × 0.625° طول، وليس 1 كم. لا ينبغي تعميمه على المملكة أو عرض نتيجة للخلية كدقة موضعية للغابة.

بيانات الطقس التاريخية استُخلصت من NASA POWER/MERRA-2؛ البيانات القريبة من الوقت الحالي قد تكون من GEOS-IT. تشابه الحقول لا يثبت تطابق توزيعات المصدرين، ويلزم تقييم مستقل لتأثير هذا الاختلاف. دربنا النموذج على رصود Suomi NPP التاريخية؛ لم نختبر نقله إلى أقمار NOAA-20/21. الموقع يستعمل MODIS وVIIRS في جوانب أخرى، لكن **هذا النموذج دُرّب على VIIRS وحده**.

## نتائج المراجعة

التدريب: 2020–2023، المعايرة: 2024، تقييم استرجاعي على 2025. من 171 خلية × يوم احتوت رصدًا في 2025، احتوى أعلى 10% من كل نتائج النموذج السنوية على 52 حالة، مقابل 57 للمرجع التاريخي. هذه ليست نسبة دقة للنموذج ولا عدد حرائق مستقلة. كانت سنة 2025 قد استُعرضت في التجربة السابقة، فلا تعتبر اختبارًا نهائيًا مستقلًا تمامًا بعد اختيار هذا التطوير.

النسب في بعض الشرائح غير معايرة جيدًا، لذلك لا تُعرض كاحتمال حريق. قد يكون الهدف نفسه خاطئًا أو ناقصًا: غياب رصد VIIRS لا يثبت عدم حدوث حريق، كما أن بعض المنشآت أو الأنشطة البشرية قد تظهر كبؤر حرارية رغم الفلترة. الملف `results/metrics.json` يحوي الأرقام والتفاصيل.

## كيف اختبرنا الإضافة؟

نجح اختبار الحساب بين Python وJavaScript لخمس حالات، وفحص تغيير اليوم في توقيت السعودية، وحدود المنطقة، ورفض البيانات الناقصة، وتشغيل معالج API في حالتي النجاح والفشل باستخدام قيم NASA الحقيقية التي رُصدت يوم 14 نوفمبر لخلية 18.5 شمالًا و42.5 شرقًا. فُحصت أيضًا قيم NASA لخلية الباحة الافتراضية. هذا اختبار محلي ببيانات مرجعية، وليس اختبارًا للخدمة المنشورة.

لم نستطع تشغيل `npm ci` أو بناء واجهة React كاملة في بيئة العمل لعدم توفر حزم الموقع في ذاكرة npm المحلية وتعذّر تنزيلها من بيئة التنفيذ. لهذا يجب تنفيذ أمرَي فحص API وبناء الواجهة المذكورين أعلاه في جهاز أو بيئة بناء الفريق قبل النشر. كما لم نتحقق بصريًا من الواجهة الجديدة أو نحاول الادعاء أنها أصبحت متاحة على الموقع.

لإعادة فحوص النموذج في بيئة التطوير بعد تطبيق الرقعة:

```bash
SAFIRE_ROOT=/path/to/SAFIRE node /path/to/FireGuardian_LiveAI_Integration/test_integration.mjs
```

تعمل اختبارات الحساب الأساسية على Node 20+، ويحتاج اختبار المعالج الإضافي لواجهة إزالة أنواع TypeScript التي يوفرها Node الحديث؛ إذا لم تتوفر، يُتخطى اختبار المعالج مع توضيح ذلك. لإعادة التدريب، استخدم `train_model.py` مع جدول `research_panel.csv` من حزمة البحث السابقة، أو عيّن مساره في متغير `RESEARCH_PANEL`.
